# 딥모드 조정안과 우리 돈의 기준표

사용자가 승인한 보완 범위: 기존 계산·AI·합의 흐름을 유지하면서 결과를 실제 대화와 실행 기준으로 연결한다. 백엔드/API만 구현하며 프론트 화면 변경, 유료 AI 호출, 배포는 별도다.

## 흐름

공동 리포트 → 전체 대화 가이드 → 조정안 미리보기 → 기존 기준표 제안/양측 확인 → 기준표 요약.

- `GET meeting/guide`: 기존 응답에 현재 round/planVersion/sourceReportId와 각자 지키고 싶은 개인비·저축 금액을 추가한다. 논의 상태가 서로 다르면 확인 질문을 제공한다. 같은 답변도 실제 합의의 증거는 아니다.
- 개인비·저축 희망액은 자기보고 기준이다. 기존 지출/목표와 겹칠 수 있으므로 현금흐름에서 다시 빼거나 지급 능력을 판정하지 않는다. 재무 공유가 양측 허용된 경우에만 반환한다.
- 기존 불변 리포트와 계산 버전은 변경하지 않는다. 새로운 질문과 기준은 guide에서 현재 공개된 라운드 입력을 이용해 구성한다. 기존 방도 새 라운드 없이 보완된 가이드를 볼 수 있다.
- `POST meeting/preview`: 클라이언트는 현재 기준 참조와 조정안만 전송한다. 원안은 서버의 공개된 리포트에서 가져온다. 같은 월/항목에서 분담 공백의 전후 변화만 계산한다. 주거자금 공백·월 적자·목표 부족이 해소됐다는 뜻은 아니다.
- 미정과 0, 추정과 확정 입력을 구분한다. 두 분담액의 합은 안전한 정수 범위를 넘을 수 없다. 재무 공유 없이 계산하거나 상대의 비공유 상한을 노출하지 않는다.
- 양쪽이 같은 지원 버전으로 상대 공유에 동의한 최신 추가 답변의 자기보고 상한만 검토한다. 기존 양측 공유 조건은 유지하며 AI 동의는 필요 없다. 한쪽 철회·미공유·버전 혼합이면 양쪽 상한을 숨긴다. 미공유/미정 상한을 무제한 여력으로 취급하지 않는다.
- 월/공동비 항목/예산 변경은 기존 새 라운드 절차로 보낸다. 동일 예산의 알려진 금액이 상한을 넘지 않는 경우에만 기존 agreement API에 넣을 terms 초안을 제공한다. 초안은 저장·동의가 아니며 실제 분담 가능성 보장도 아니다.
- 기존 월 분담 기준표가 있으면 `review_agreements`와 현재 기준표를 반환한다. 프론트는 기존 안을 선택해 최신 버전으로 수정하도록 연결하고 새 기준표를 자동 중복 생성하지 않는다. 빈 예산 입력은 삭제 요청이 아닌 `complete_numbers`다.
- 조정안은 모두 입력했지만 원안 분담액이 미정인 경우 `revise_inputs`로 기존 새 라운드의 개인 입력 보완을 안내한다. 불변 원안을 현재 미리보기에서 덮어쓰거나 같은 숫자 입력을 반복 요구하지 않는다.
- `GET meeting/standards`: 현재 라운드의 기준표를 양측 확인/제안/보류로 구분하고 담당자·시작월·납부일·예외·재검토일을 유지한다. 가장 이른 합의된 재검토일과 전체 논의 질문을 함께 제공한다. 같은 주제의 기준표가 있다는 이유만으로 질문을 해결 처리하지 않는다.
- 미리보기/요약은 데이터 변경과 유료 AI 호출 없이 동작한다. 현재 AI 근거 슬롯/전송 범위는 그대로 유지한다.

## 수용 사례

공동비 200만/A 80만/B 80만 → 공백 40만. A 100만/B 80만 → 공백 20만. 예산 180만으로 변경 → 공백 0이지만 새 공동 계획 확인이 필요하다. 원래 리포트와 합의는 유지된다.

A는 합의했다고, B는 논의 중이라고 답했다면 금액·포함 항목·시작일의 인식을 확인한다. 이미 수집한 개인비·저축을 반복 입력시키지 않는다. 양측 확인한 기준표를 한쪽이 수정하면 요약에서도 다시 제안 상태이며 이전 확인은 해제된다.
