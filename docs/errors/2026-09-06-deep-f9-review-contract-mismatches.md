# F9 미러와 서버 계약의 경계가 어긋난 문제

- 작성일: 2026-09-06
- 관련: 이슈 #81, PR/커밋 없음 (코디네이터 통합 예정)

## 무엇이 잘못됐나

F9 1라운드 리뷰에서 서버가 허용하는 연이율 문자열을 Zod 미러가 거부하고, v3가 허용하지 않는 63~64자 ID를 생성하며, 계획 미러가 존재하지 않는 날짜를 통과시키는 문제가 발견됐다. funding sources/settlements의 비공개 컬렉션 오류 코드도 실패 회귀 테스트가 없어 분기 회귀를 잡지 못했다.

## 원인

- **설계적 원인**: 서버의 Decimal/date 및 v3 식별자 제약을 미러와 생성기 설계에 끝까지 반영하지 않았다.
- **코드적 원인**: 두 스키마의 연이율 정규식 리터럴이 `\\d`를 사용했고, 계획 날짜 검사가 모양만 확인했으며, funding ID 접두사 절단 상한이 일반 ID의 64자 상한에 맞춰져 있었다.

## 해결

연이율은 백슬래시만 고치지 않고 서버 Decimal의 부호·유한성·`max_digits=14`·`decimal_places=10` 제약을 문자열과 숫자 모두에 적용했다. 실제 달력 날짜 판정을 shared helper로 내려 deep-input과 deep-plan이 같은 검사를 사용하게 했고, 생성 ID는 v3 상한인 62자 이내로 절단했다. funding sources와 settlements가 known이 아닐 때 각각 `FUNDING_ITEMS_REQUIRE_KNOWN_COLLECTION`을 내는 실패 테스트도 추가했다.

## 재발 방지

두 미러 테스트가 정상 연이율(`1.5`, `0.035`, 숫자 `0.035`, `null`)과 음수/비숫자 입력을 고정하고, 계획 미러 테스트가 `2026-99-99`와 `2026-02-31`을 거부한다. 긴 접두사 ID 테스트는 62자 상한을 단언하며, 전체 프론트 검증 5종을 통과시켰다.
