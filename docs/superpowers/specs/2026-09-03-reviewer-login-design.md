# 심사용 로그인과 독립 체험방

사용자는 카카오 설정을 보류하고 심사용 로그인 A/B 및 편리한 초기화 방식을 맡겨 구현을 요청했다. 기존 Deep 설계의 일반 사용자 동의/계산/합의 계약은 유지한다. 이번 작업은 백엔드이며 운영 배포·비밀번호 공개·AI 호출은 포함하지 않는다.

## 결정

공용 계정의 모든 데이터를 지우는 방식은 동시 심사를 방해한다. 매 로그인마다 자동 초기화하는 방식은 새로고침/재로그인 시 진행을 잃는다. 따라서 **공용 자격증명 2개 + 독립 체험방 + 명시적인 처음부터 다시 체험**을 선택한다.

- 로그인 이름은 `judge-a`, `judge-b`. 비밀번호는 운영자가 별도로 설정하며 PBKDF2-HMAC-SHA256 600,000회, 무작위 salt의 해시만 서버 설정에 저장한다. 자체 회원가입/관리자 기능은 없다.
- 방 코드 없이 로그인하면 만료 24시간의 새 방과 독립 사용자 A/B를 만든다. 같은 방 코드와 다른 계정으로 로그인하면 그 방의 상대역이 된다. 같은 코드 재로그인은 동일한 사용자를 복원한다.
- 방 코드는 256비트 HMAC 기반 capability이며 로그인 비밀번호도 함께 필요하다. URL/query/log에 넣지 않고 POST body 또는 인증 후 context 응답에서만 전달한다.
- `POST /api/v1/auth/reviewer/login`: username/password/roomCode(optional). `GET /api/v1/auth/reviewer/context`: 현재 역할/방 코드/만료. `POST /api/v1/auth/reviewer/reset`: 현재 방의 어느 역할이든 confirm=true를 보내면 방을 원자적으로 닫고 새 방으로 이동한다. 이전 양쪽 로그인은 무효가 되고 상대역은 새 방 코드로 재로그인한다. 동시 reset의 한 요청만 성공한다.
- reset은 물리 삭제가 아니다. 이전 데이터는 즉시 접근 차단하고 TTL로 정리한다. 방/사용자/인증/심사용 Deep 데이터의 최대 보관은 생성한 방 만료 시각까지, Mongo TTL의 실제 삭제 지연 가능성은 별도다. 리포트 공개도 방 만료를 연장하지 않는다.
- 심사용 세션은 다른 심사방 또는 실제 카카오 사용자와 초대/합류할 수 없다. Deep에서 저장된 방 scope를 매번 확인하며 인증 이후 reset/만료 경합에도 재검사한다.
- 기존 `mrs_account` 쿠키와 내부 Principal을 재사용. HttpOnly, production Secure, SameSite=Lax, Origin 검사를 유지한다. 비밀번호/방 코드는 응답 오류·로그에 포함하지 않는다.
- `REVIEWER_LOGIN_ENABLED=false` 기본, `KAKAO_LOGIN_ENABLED=true` 기본. Deep는 켜고 Kakao는 끈 상태에서 reviewer만 작동 가능하다. reviewer를 끄거나 해시를 변경하면 기존 심사용 로그인도 거부한다. 실제 Kakao 설정/Light 쿠키는 변경하지 않는다.
- Mongo 공유 rate limit: 로그인 IP당 10분 20회 및 전체 10분 200회, reset IP당 10분 10회. 실패한 비밀번호도 카운트한다. 비밀번호 해시는 threadpool에서 검증한다.
- 삭제 계정의 같은 방 역할은 복원하지 않는다. 방 코드를 생략해 새 체험을 시작한다. 일반 사용자/실제 운영 자료에 대한 초기화는 제공하지 않는다.

## 검증과 전달

테스트 먼저: Kakao 키 없는 reviewer 설정, 비밀번호 오류, Origin, rate limit, A/B 복원, 방 간 및 실계정 경계, reset 경합/만료, 민감값 오류 비노출, Deep 기존 흐름 회귀. Mongo 경합 테스트는 전용 로컬/CI 데이터베이스에서만 실행한다.

프론트는 로그인 폼, 방 코드 복사/붙여넣기, 확인 대화상자가 있는 초기화 버튼을 연결해야 한다. 심사용 데이터임과 실제 정보를 입력하지 말라는 안내를 표시한다. 백엔드 작업에서는 프론트 UI를 임의 구현하지 않고 OpenAPI와 사용 안내를 제공한다.
