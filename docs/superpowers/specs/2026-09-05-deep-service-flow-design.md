# 딥모드: 답변에서 두 사람의 기준으로

2026-09-05 사용자 승인 방향. 서비스 축소나 짧은 문장 자체를 목표로 하지 않는다.
기존 [질문 파이프라인](2026-09-03-deep-question-pipeline-final-design.md)과
[AI 해설 설계](2026-09-04-deep-money-meeting-design.md)의 후속 기준이다.

## 서비스의 목표

관찰된 사실 → 계획에서의 의미 → 답변에 맞는 조정 방향 → 지금 정할 질문 → 제안/양측 확인/보류.
주거자금·반환/상환 시점·월 생활비·목표·가치관·수용 조건을 유지한다.
최초 카드 세 개는 우선순위 표시일 뿐 전체 문제를 삭제하는 제한이 아니다.
관계 유형은 필수로 추가하지 않는다. 이미 받은 답은 재질문하지 않으며, 질문의 답은 반드시 다음 판단에 사용한다.

## 동의와 자연스러운 해설

- 단계마다 팝업을 띄우지 않고 각자의 답변이 끝나는 화면 하단에 안내와 선택을 모은다.
- 상대 공유와 외부 AI 처리는 기본 미선택의 별도 선택이다. 선택하지 않아도 기존 공동 결과는 이용한다.
- 기본 재무/가치관 공유는 기존 제출 과정에서 확인한다. 결과 후 새로 얻은 추가 답변은 그 답변 하단에서 한 번 확인한다.
  미래에 입력할 내용을 처음 동의로 포괄 허용했다고 취급하지 않는다.
- 추가 답변은 `POST /meeting/complete` 한 번으로 답변·현재 범위의 동의를 원자 저장한다.
  AI 선택 시 같은 명시적 행동의 연속으로 양측 최신 동의를 검사하고 생성한다. 별도 비용/모델/생성 버튼은 필요 없다.
- 처음 완료한 사람은 기존 공동 결과를 즉시 이용한다. 나중 완료한 사람의 요청이 생성한 해설을 GET으로 확인한다.
  GET은 생성하지 않는다. 재방문·새로고침으로 동의·생성 POST를 재전송하지 않는다.
- 답변 수정·범위 변경·철회 후에는 재확인한다. 실패/409 뒤에는 현재 저장 상태를 조회하고 다시 확인한다.
- AI는 합의 저장이나 확인을 대신하지 않는다. 금액·범위·날짜·예외와 양쪽의 같은 버전 확인을 구분한다.

## 백엔드 우선 구현 단위

1. **이번 단위:** 추가 질문 설명, 답변별 대화 방향, 완료 API, 기존 AI 생성/조회 연결, 영속 누적 예산, 프론트 계약.
2. **다음 단위:** 공동 리포트의 실제 우선순위와 질문/결정 항목 매핑. 주거 날짜·월 적자·목표·수용 조건을 생활비 분담과 구분.
3. **이후 단위:** 주요 영역의 최소 근거를 AI에 투영하고 근거별 사례 평가. 새 전송 범위/동의 버전과 배포 전 법적 근거 검토가 선행된다.
4. **연결 단위:** 기존 기준표의 제안·예외·재확인일·양측 확인/보류 연결과 프론트 소비 검증.

순서는 기능 삭제가 아니다. 현재 월 분담용 AI 동의로 주거·자산·부채 원장을 추가 전송하지 않는다.
이번에는 프론트 화면을 재구축하지 않고 서버 기능과 계약을 전달한다. 실제 화면 자동 조회는 프론트 연결 작업이다.

## 동의의 법적 검토 경계

동의 UI를 한 곳에 배치하는 것과 서로 다른 처리 목적을 한 동의로 묶는 것은 다르다.
중요 내용과 선택을 구분하는 방향은 개인정보 보호법 제22조를 참고했다.
국외이전에 동의를 법적 근거로 사용할 경우 제28조의8의 별도 동의·고지 사항을 검토해야 한다.
수탁/제공 관계, 이전 국가·수령자·연락처·시기/방법·보관기간·거부 방법/영향은 실제 계약/운영 설정으로 확정한다.
법적 검토 완료 또는 현재 안내문만으로 모든 의무 충족이라고 표시하지 않는다.
현재 동의 v2의 데이터 범위·문구는 이번 단위에서 바꾸지 않는다. 새 범위는 새 동의 버전으로 구현한다.

## 호출 예산

새 완료 경로의 유료 생성은 일일 한도와 별도로 평가 누적 예산 설정을 요구한다.
상한 최대 5,000,000 micro-USD, 이전 호출/실패/진행 중 예약분의 감사된 선차감값을 명시한다.
누적 원장은 날짜/서비스 재시작/심사방 초기화로 사라지지 않는다. 불확실한 시도는 환급하지 않는다.
설정 전에는 완료·동의 저장과 기본 결과는 가능하지만 새 완료 경로의 유료 호출은 막는다.
모델 단가 변경·다른 시스템 호출·세금까지 포함한 청구서 절대 상한을 약속하지 않는다.

## 수용 기준

- A/B가 하단에서 각자 한 번 완료하면 마지막 요청에서 AI 생성, 이후 양측 GET은 같은 결과.
- 미동의/상대 미준비는 상대 거절 여부를 드러내지 않고 waiting. 기존 공동 결과는 별도 유지.
- 잘못된 답변은 동의와 함께 저장되지 않는다. stale 요청은 철회를 덮어쓰지 않는다.
- 저장 직후 본인 답변이 바뀌면 기존 클릭으로 새로운 답변을 생성하지 않는다.
- 양측 동시 완료·중복 요청에서도 같은 컨텍스트의 유료 호출은 최대 한 번.
- 알려진 상한을 다시 묻거나 조정 의사를 확정 약속으로 바꾸지 않는다. 미정과 0원을 구분한다.
- 누적 예산은 자정/재시작 후 유지, 경합 시 한도 초과 호출 없음, 실패/불명 시도 포함.
