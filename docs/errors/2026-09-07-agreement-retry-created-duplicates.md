# 합의안 재시도가 중복 제안을 만들었다

- 작성일: 2026-09-07
- 관련: 이슈 #72

## 무엇이 잘못됐나

네트워크 재시도로 같은 합의안 생성 요청을 다시 보내면 서로 다른 ID의 합의안이 두 건 만들어졌다. 딥 v3 통합 테스트에서 같은 멱등성 키로 요청을 두 번 보내 재현했다.

## 원인

- **설계적 원인**: 세션 생성·초대 수락에만 적용한 멱등성 계약을 합의안 생성에는 적용하지 않았다.
- **코드적 원인**: `apps/backend/deep/router.py`와 `apps/backend/deep/v3_router.py`가 합의안 생성에서 `Idempotency-Key`를 받지 않았고, `apps/backend/deep/repository.py`가 매 요청마다 새 UUID를 만들어 삽입했다.

## 해결

합의안 생성도 `Idempotency-Key`를 필수로 받고, 세션·라운드·작성자·키 조합을 유일 인덱스로 저장한다. 같은 키와 같은 본문은 기존 합의안을 반환하고, 같은 키와 다른 본문은 `IDEMPOTENCY_CONFLICT`로 거절한다. 기존 API의 재시도 패턴과 일관되며 동시 재시도도 유일 인덱스로 막을 수 있다.

## 재발 방지

같은 키 재전송·다른 본문 충돌 통합 테스트를 추가했다. 프론트 전달 문서와 OpenAPI에 새 합의안마다 새 키, 재시도에는 기존 키를 사용해야 한다는 계약을 기록했다.
