# 딥모드 프론트 전달 전 백엔드 기능 완결 인계

2026-09-05, `codex/deep-money-meeting` 로컬 작업. 커밋·푸시·배포·유료 AI 호출과 구분한다.

## 구현

- `GET /api/v1/deep/v3/sessions/{id}/meeting/guide`가 공개된 전체 계산 쟁점과 가치관 차이, 상위 세 개,
  질문의 의미/저장 대상, 기존 기준표의 제안·양측 확인·수정 시 확인 해제·보류 상태를 반환한다.
  읽기만으로 입력이나 합의를 바꾸지 않으며 AI 동의도 요구하지 않는다.
- `money-meeting-consent-v3`를 추가했다. 양측 v3에서만 주거·월 현금흐름·목표·조건 존재의 최소 근거를 투영한다.
  양측 v2는 기존 월 분담 해설로 호환하고 혼합 버전은 상대 선택을 드러내지 않는 waiting이다.
- 확장 해설은 날짜별 누적 부족을 더하지 않고 최초 부족일 한 건을 사용한다. 미정과 0을 구분하고
  주거 공백·월 적자·목표 적립 부족을 서로 합치지 않는다. 원문 목록/메모/계정/합의 원문은 공급자 입력에서 제외한다.
- 서버가 우선순위 최대 세 개의 쟁점과 각 fact를 고정하고, AI에는 선택된 근거 슬롯만 보낸다.
  AI는 같은 순서의 해설·질문 텍스트만 생성하며 `issueId`와 `factIds`는 응답에 포함하지 못한다. 서버가 이를 원래 슬롯에 결합하고 검증한다.
- 실제 확장 공급자 호출은 기존 AI 플래그 외 `DEEP_MEETING_AI_EXTENDED_ENABLED=true`와 영속 누적 예산 설정을 요구한다.
  기본은 템플릿이며 GET은 유료 호출을 만들지 않는다.

## 프론트 연결

[상세 API](../deep-meeting-api.md), [운영 설정](../deep-meeting-operations.md),
[전달용 가이드](../../apps/backend/frontend-handoff/02-api-guide.md), 같은 폴더의 `04-openapi.json`을 따른다.
`/result` ready → `/meeting/guide` → `/meeting/me` 질문 → 하단 `/meeting/complete` → 설명/기준표 흐름이다.
AI 카드 세 개 뒤에도 guide의 나머지 쟁점을 삭제하지 않는다. 숫자는 구조화 fact로 표시한다.

## 검증과 남은 운영 경계

- guide/합의 생명주기, v2 호환과 버전 혼합, 확장 플래그/누적 예산, 엄격 날짜·수치·산술·우선순위·정보 최소화 테스트를 추가했다.
- 전체 로컬 suite 622 passed / 23 skipped / 기존 경고 11개. 변경 모듈 Ruff와 mypy, 프론트 타입 검사,
  OpenAPI 연속 생성 결정성 및 전달본 해시 일치를 확인했다.
- 별도 읽기 전용 리뷰에서 주거 조건의 decision topic과 AI의 카드/핵심 fact 누락을 발견해 수정했다.
- `money-meeting-v7-selected-evidence-slots` 합성 사례 한 건은 실제 모델 형식·근거 결합을 통과했다. 입력 875·출력 296토큰,
  추정 비용은 $0.001989였다. 이는 전체 품질 평가를 대신하지 않는다.
- 다수 사례의 실제 모델 품질 평가, 실제 Mongo 동시성, 프론트 E2E, 개인정보 고지 검토, Railway 변수/배포는 수행하지 않았다.
  운영 활성화는 별도 승인이 필요하다.
