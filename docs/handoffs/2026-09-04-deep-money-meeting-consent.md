# 우리 돈의 기준회의 — B단계 인계

2026-09-04. `codex/deep-money-meeting`, 기준 develop `a62efe9`. A단계 변경을 보존하고 이어서 구현했다.
계획: [B단계 실행 계획](../superpowers/plans/2026-09-04-deep-money-meeting-consent.md).
프론트 계약: [추가 질문·동의 API](../deep-meeting-api.md).

## 구현

- 고정 추가 질문 두 항목: 제안/본인 상한/미정 구분, 늘릴 수 있는 월 상한 선택 입력.
- 현재 round/plan/report에 묶인 개인 답변·동의를 `deep_sessions.meeting`에 저장한다.
  별도 컬렉션/의존성 없이 기존 세션 TTL·멤버/심사방 검사·단일 문서 CAS를 사용한다.
- GET/PATCH `/meeting/me`, POST/DELETE `/meeting/me/consent`, GET `/meeting/context`를 기존 v3 인증 경로에 추가했다.
- 본인 답변 변경은 본인 동의를 지운다. 동의 변경도 revision을 증가시켜 오래된 동의 요청을 차단한다.
- 양측 동의 전에는 공동 준비 조회가 waiting만 반환한다. 동의 후에는 A단계 근거와 구조화된 추가 답변을 반환한다.
- 조회 중 철회/상태 변경은 문서 버전 재검사로 거부한다. 새 round 및 withdraw가 meeting을 지운다.
  이미 닫힌 세션에 대한 withdraw 재시도도 남은 meeting을 정리하도록 보완했다.
- OpenAPI 원본/프론트/전달본 세 사본과 프론트 생성 타입을 갱신했다. 화면은 만들지 않았다.

## 검증 기록

- 새 경로가 404로 실패하는 것을 확인한 뒤 구현했다.
- 새 API/저장소 29개 + A단계/기존 v3/OpenAPI 회귀를 합쳐 112개를 우선 확인했다.
- 최종 재검증은 위 범위에 기존 세션·라이프사이클·심사용 로그인 통합 테스트를 더해 **143 passed**.
- 실제 저장소 메서드와 기존 MemoryDatabase 대역으로 동시 CAS 경쟁·오래된 동의·조회 도중 철회·재작성·계정 삭제를 검증했다.
- 이미 닫힌 세션에 추가 데이터가 남는 회귀 테스트의 실패를 확인하고 withdraw 재시도 경로를 고쳤다.
- Ruff, mypy `deep` 및 새 테스트 파일, 프론트 `tsc --noEmit` 통과.
- 기존 API 경로/컴포넌트 스키마의 의미적 변경 없음, OpenAPI 세 사본 해시 일치, 생성 타입 재생성 완료.
- 읽기 전용 코드 리뷰에서 B단계의 실질적 결함을 발견하지 못했다. 추적 diff와 새 파일 공백 검사 통과.
- 기존 Starlette/httpx 및 HTTP 422 명칭 deprecation 경고는 이번 기능과 별개다.

실제 Mongo 경쟁/실계정 쿠키·카카오/브라우저 연결/AI 품질/배포는 이번 검증 범위가 아니다.
MemoryDatabase 경쟁 테스트는 실제 MongoDB의 통합 검증을 대체하지 않는다.
