# 미리살림(MIRI) 프로젝트 에이전트 개발 규칙 및 가이드라인

## 1. Git 원격 저장소 및 Git Flow 표준 준수 원칙 (절대 규칙)

- **원격 저장소(`origin`) 표준 고정**:
  - 미리살림 공식 원격 저장소(`https://github.com/hotpringles/MIRI.git`)가 반드시 기본 **`origin`**으로 설정되어야 합니다.
  - 에이전트가 임의로 원격 저장소 이름을 바꾸거나(`team` 등으로 분리), 다른 개인 저장소를 혼용하여 작업 흐름을 변경해서는 안 됩니다.
- **브랜치 작업 및 푸시 기준**:
  - 모든 기능/수정 작업은 task 단위 브랜치(`feat/<기능명>`, `fix/<이슈명>`)에서 진행합니다.
  - 작업 완료 후 푸시는 항상 **`git push origin <작업브랜치명>`** 명령어를 기준으로 `origin`에 푸시합니다.
  - `main` 또는 `develop`에 직접 커밋하지 않으며, `origin/develop`을 타겟으로 PR을 생성하여 협업합니다.
- **원격 설정 불변성**:
  - 사용자의 명시적인 사전 지시나 승인 없이 원격 저장소 URL 및 remote 명칭을 임의로 변경하거나 다른 리모트를 추가하지 않습니다.

## 2. 선제적 API 계약 및 DTO 설계 원칙 (수동적 대처 금지)

- **선제적 요구사항 검토**:
  - 외부 지적이나 타 AI 도구의 사후 수정을 기다리지 않고, 백엔드 DTO 및 엔드포인트 설계 시 프론트엔드 연동 요구사항을 선제적으로 완벽하게 충족해야 합니다.
- **민감 데이터 보호 및 최소 공개 원칙**:
  - 결과 화면 및 공유 모델에서 소득·부채·저축액 등 금액 정보가 불필요하게 노출되지 않도록 철저히 분리합니다.
  - 초대 미리보기 및 세션 상태 조회 시 답변, 예측, 점수 등 민감 정보가 포함되지 않도록 최소 정보만 제공합니다.
- **가변 구조 및 확장성 보장**:
  - 질문 수(3개, 5개, 7개 등)가 변경되더라도 DTO 변경이 발생하지 않도록 가변 배열 구조를 선제적으로 적용합니다.
- **보안 스킴(`cookieAuth` 등) 명시적 연결**:
  - 인증이 필요한 모든 보호 API 엔드포인트에는 OpenAPI 스펙 상 `security` 항목을 빠짐없이 연결합니다.

## 3. 원스톱 완결 검증 루프 (Verification Loop)

- 작업 완료 전 반드시 아래 4단계 자체 검증을 실행하고 모두 100% 통과(Exit Code 0)한 상태에서 보고합니다:
  1. **Ruff 린트 검증**: `python -m ruff check apps/backend`
  2. **Mypy 타입 검증**: `python -m mypy apps/backend/...`
  3. **Pytest 단위/계약 테스트**: `python -m pytest apps/backend/...`
  4. **OpenAPI 동기화 & Clean Diff**: `python apps/backend/export_openapi.py` (백엔드와 프론트엔드 openapi.json 100% 일치 확인)
