# 저장하지 않은 공동 계획을 확인할 수 있었던 문제

- 작성일: 2026-09-06
- 관련: 이슈 #94, PR 미정, 커밋 미정

## 무엇이 잘못됐나

F11 계획 화면에서 사용자가 계획을 수정한 뒤 저장하지 않고 `이 계획 확인하기`를 누를 수 있었다. 그러면 화면의 초안과 서버의 계획 버전이 달라도 서버에는 저장 전 버전이 확인되어, 사용자가 확인했다고 생각한 내용과 두 사람이 확인한 내용이 달라질 수 있었다.

페이지 흐름 테스트에서 저장되지 않은 시작월 변경 직후 확인 버튼의 활성 상태를 점검하는 회귀 테스트로 발견했다.

## 원인

- **설계적 원인**: 공동 계획은 명시적으로 저장하고 저장할 때 확인을 초기화해야 하는 공유 문서인데, 초안 편집 상태와 서버 버전을 별도 상태로 표현하지 않은 채 확인 액션을 항상 열어 두었다.

## 해결

서버에서 hydrate한 계획과 현재 초안을 JSON 비교해 dirty 상태를 계산하고, 변경분이 있으면 확인 버튼을 비활성화하며 `저장한 뒤 이 계획을 확인할 수 있어요.`를 안내한다. 자동저장은 상대 확인을 타이핑마다 해제하므로 사용하지 않고, 저장 전 리셋 경고를 거친 명시적 저장을 유지했다.

## 재발 방지

`DeepPlanPage.test.tsx`가 미저장 편집의 확인 차단을 검증한다. 공유 CAS 문서는 확인 요청 전에 서버 기준 계획과 초안의 차이 및 최신 버전을 함께 점검한다.
