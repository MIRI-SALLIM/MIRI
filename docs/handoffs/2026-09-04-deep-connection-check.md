# 임시 딥모드 연결 점검

## 범위

기존 `/deep/login-check`에 두 사람의 Deep v3 흐름을 연결했다. 디자인 완성본·전체 질문 입력 UI가 아니라 **합성 데이터 전용 점검 화면**이다. API 계약과 운영 코드는 변경하지 않았다. 실제 인증·쿠키·Deep 서비스·계산·동의·기본 해설을 사용하고 저장소만 MemoryDatabase로 교체한다.

## 로컬 실행

저장소 루트의 PowerShell 터미널 두 개에서 실행한다. 8000·5173 포트는 비어 있어야 한다.

```powershell
Set-Location apps/backend
.venv/Scripts/python.exe -m tests.manual_server
```

```powershell
npm run dev --workspace apps/frontend -- --host 127.0.0.1 --port 5173 --strictPort
```

접속: http://127.0.0.1:5173/deep/login-check

Vite의 `MIRISALLIM_API_PROXY_TARGET`을 다른 서버로 설정하지 않아야 한다. 기본 대상은 `http://127.0.0.1:8000`이다. 임시 서버는 `PUBLIC_APP_ORIGIN=http://127.0.0.1:5173`을 사용하므로 localhost나 다른 포트를 섞지 않는다.

**이 서버에서만 쓰는 공개 합성 계정**:

| 계정 | 로컬 테스트 비밀번호 |
|---|---|
| judge-a | synthetic-password-a |
| judge-b | synthetic-password-b |

운영 비밀번호가 아니며 Railway에 넣으면 안 된다. 서버는 `.env.ai-smoke.local`이나 실제 심사용 자격증명을 읽지 않는다. 시작 시 새 pepper·암호 해시를 만들고 AI·카카오·Mongo 접속을 끈다. production/prod 및 Railway 프로젝트 환경에서 실행을 거부한다. 데이터와 로그인은 재시작하면 사라진다. 이 모듈을 운영 실행 명령으로 사용하지 않는다.

## 점검 순서

1. A는 체험방 코드를 비워 로그인한다. **체험방 코드**, 진단 생성 후 **진단 초대 코드·진단 ID**를 임시로 보관한다. 로그인 코드와 진단 초대 코드는 서로 다르다.
2. A만 `샘플 공동 계획 저장`을 누른다. A는 `내 샘플 입력 저장` → `공동 계획 확인` → 재무·가치관 공유 체크 → 제출한다.
3. 별도 브라우저 또는 A 로그아웃 후 B로 같은 **체험방 코드**를 넣어 로그인한다. **진단 초대 코드**로 참여한다. B는 공동 계획을 다시 저장하지 않고 자신의 입력 저장·계획 확인·동의·제출만 한다.
4. `공동 리포트 조회`로 ready 결과를 만든다. 그 뒤에 추가 질문을 열 수 있다. 보고서 준비 전 추가 질문은 409다.
5. 각자 추가 답변을 저장한다. 저장 후 상대 공유·AI 처리 동의는 별도로 체크·저장해야 한다. B는 `현재 제가 제시할 수 있는 상한`, A는 `우선 제안` 및 상한 1200000원으로 확인했다.
6. 같은 브라우저에서 A로 돌아갈 때는 같은 체험방 코드로 로그인하고 `기존 진단 ID`로 연다. 새 진단을 만들지 않는다.
7. `해설 조회 (생성 안 함)`는 무료 GET이며 자동 생성하지 않는다. 로컬 서버는 `source=template, reason=disabled`다. AI 생성 버튼은 별도 비용 확인 체크가 필요하지만, 이번 브라우저 검증에서는 누르지 않았다.
8. `해설 동의 철회`는 화면의 해설을 지우고 이후 조회를 waiting으로 돌린다. `새 체험방으로 초기화`는 별도 확인 체크 후 사용한다. 이전 체험방의 두 계정 세션·진단은 더 이상 사용할 수 없다.

새로고침·로그인 상태 확인은 임시 진단 화면 상태를 비운다. 로그인은 쿠키로 복원하고 진단은 ID로 다시 연다. 비밀번호·방 코드·리포트는 localStorage/sessionStorage에 저장하지 않는다. 공유·AI 동의 체크 해제만으로 서버 동의가 철회되는 것은 아니므로 철회 버튼을 사용한다.

## 실제 확인 결과 (2026-09-04)

- 브라우저 → Vite 프록시 → 실제 FastAPI 인증 → 메모리 저장소 → 공동 계산 결과 연결 성공.
- A/B 같은 체험방 로그인, 초대 참여, 개별 입력·계획 확인·제출, 로그아웃·재로그인 및 진단 ID 복구 성공.
- A만 제출하면 waiting, 두 사람 제출 후 ready.
- 공동 예산 2,000,000원, 합산 제안 1,600,000원, **부족액 400,000원**. 양측 기대 차이도 각각 400,000원.
- 추가 질문·동의 안내는 서버 응답 문구를 표시한다. 각자 동의 전 해설은 waiting.
- 기본 해설에 `B가 밝힌 상한`과 `B의 상한을 유지하면서 A의 조정 가능 범위와 공동 예산 축소`가 표시됨.
- 철회 직후 카드 0개, 다음 조회 waiting. 캡처된 브라우저 오류 로그 없음.
- 새 유료 API 호출 0회. 배포·커밋·원격 푸시는 수행하지 않음.
- 프론트 관련 테스트 10개, 백엔드 관련 테스트 49개 통과. TypeScript 검사·변경 파일 ESLint·diff 공백 검사 통과. 백엔드 기존 Starlette deprecation 경고 2건은 남아 있다.
- 별도 변경 코드 리뷰에서 수정이 필요한 P1/P2 문제는 발견되지 않았다.

## 아직 남은 것

- 카카오 실제 계정 인증: 시작 링크와 일반 계정 복원 경로만 연결됨. 키·등록 콜백·실계정 동의가 준비된 서버에서 별도 확인 필요.
- 프롬프트 v2 실제 AI 품질 재평가: 앞선 소량 실호출 후 보완된 상한 조건을 유료 호출로 재검증하지 않음.
- 운영 브라우저/HTTPS/실Mongo 연결: 이 로컬 점검은 운영 검증을 대체하지 않음. 과거 운영 검증 기록과 구분.
- 완성형 딥모드 UI, 배포 및 실제 프론트 도메인·쿠키·리다이렉트 검증.

정책 매칭 등 이번 AI 해설 범위 밖 기능은 추가 구현하지 않았다.
