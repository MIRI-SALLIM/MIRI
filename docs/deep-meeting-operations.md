# 우리 돈의 기준회의 — AI 운영 설정

2026-09-04. 코드는 로컬 구현, 모의 API 검증 상태다. 이 문서는 운영 활성화 완료 기록이 아니다.

후속 상태: [v2 가상 3건 실호출](handoffs/2026-09-04-deep-money-meeting-v2-live-smoke.md)에서 연결·상한 반영·미정 처리를 확인했다. 이후 중복 질문 보완 v3를 거쳐 현재 로컬 프롬프트는 `money-meeting-v4-discussion-direction`이다. 답변에 따른 다음 결정을 강조했고 실모델 재호출은 하지 않았다. 운영 준비의 이전 확인은 [배포 준비 인계](handoffs/2026-09-04-deep-meeting-release-preparation.md), 새 완료 경로의 누적 설정은 아래 절을 따른다.

## Railway 설정

백엔드 서비스 Variables에만 설정한다. 프론트 번들·Git·대화에 키를 넣지 않는다.

| 변수 | 기본/의미 |
| --- | --- |
| OPENAI_API_KEY | 해당 OpenAI 프로젝트의 키. 등록만으로 AI가 켜지지 않음 |
| DEEP_MEETING_AI_ENABLED | false. 품질·권한·비용 검증 후에만 true |
| DEEP_MEETING_AI_EXTENDED_ENABLED | false. 주거·월 잔액·목표·조건 최소 근거의 외부 전송을 별도 승인한 뒤에만 true |
| DEEP_MEETING_AI_DAILY_MICRO_USD | 250000 = 모델 비용 예약 $0.25/UTC 일, 세금 별도 |
| DEEP_MEETING_AI_DAILY_CALLS | 20 = 하루 생성 시도 최대치. 금액 한도와 함께 적용 |

기존 DEEP_MODE_ENABLED·계정 인증·DB 설정도 유효해야 한다. 잘못된 한도 설정은 AI 비활성으로 처리한다.
금액 설정 허용 범위는 0~5000000, 횟수는 0~200이다. 0은 추가 생성 차단이다.
비활성 플래그는 저장된 AI 해설 노출도 멈추고 기본 해설로 전환한다. 이미 외부 전송 중인 요청을 회수하지는 못한다.

## 호출·비용 방식

- 모델은 `gpt-5.4-mini-2026-03-17` 고정, Responses API, reasoning none, 출력 800토큰, 총 20초, SDK 재시도 0회.
- 클라이언트 GET은 모델 호출을 하지 않는다. 같은 컨텍스트의 동시 POST/반복 POST는 시도 원장으로 중복을 막는다.
- 일일 한도는 서비스 공용 Mongo 원장에서 선예약한다. 현재 한 요청당 **$0.018672**를 예약하므로 기본 금액 한도에서는 최대 **13회**까지 허용한다.
- 이 금액은 예상 실제 요금이 아니다. 요청 JSON UTF-8 최대 16000바이트에 입력 여유 4096토큰과 출력 상한을 적용한 보수적 예약이다. 실제 입력 1500·출력 800토큰이면 모델 요금 예시는 약 $0.004725다.
- 실패/타임아웃/낮은 실제 사용량이어도 예약을 환급하지 않는다. 사용량이 예약 가정을 벗어나면 당일 원장과 존재하는 누적 원장을 halted로 닫는다.
- 현재 공식 단가(입력 $0.75/백만, 출력 $4.50/백만)를 고정 계산한 서버의 호출 허용 한도다. 가격 변화·숨은 토큰 산정·별도 프로젝트 호출·세금까지 포함한 청구서의 절대 상한은 아니다.
- OpenAI 대시보드의 지출/잔액도 확인한다. 실제 단가/최대 입력을 검증한 뒤 운영 예약을 조정한다. 사용자의 다른 API 호출은 이 원장을 거치지 않는다.

## 저장과 철회

- `deep_sessions.meeting.generation`: 현재 컨텍스트의 검증된 카드. 세션 TTL, 답변/동의 변경·탈퇴·새 round 시 기존 수명 규칙을 따른다.
- `deep_meeting_attempts`: 원문 없는 세션 ID·컨텍스트 해시·시도 상태/기한·성공 사용량. 세션 만료 시 TTL, 탈퇴 시 삭제. 원장을 수동 삭제하면 중복 과금 방지가 무너질 수 있다.
- `deep_meeting_budgets`: UTC 일별 예약액/횟수/halted(약 35일 TTL)와 고정 ID의 누적 원장(TTL 없음). 개인정보 없음. 재시작해도 유지하며 예산 원장을 초기화해서 한도를 우회하지 않는다.
- 확장 해설은 양측의 같은 동의 v3가 필요하다. v2끼리는 월 분담 해설만 허용하고 혼합 버전은 전송하지 않는다.
- `store=false`로 호출하지만 공급자의 남용 방지 보관까지 없는 것은 아니다. API 데이터는 기본 학습에 쓰이지 않는다. 실출시 전 개인정보 안내/처리 정책을 별도로 검토한다.
- 전송 직전·저장 전후·조회 시 현재 권한과 근거를 재검사한다. 전송 직후 철회된 데이터는 외부에서 회수할 수 없으며 결과 저장/제공을 막는다.
- 프로세스 중단이나 완료 여부가 모호한 타임아웃은 같은 컨텍스트를 다시 호출하지 않는다. 기한 지난 응답도 저장하지 않는다. 새 컨텍스트까지 기본 해설을 사용한다.

## 활성화 전 남은 검증

1. 승인받은 합성 사례로 실제 API 소량 호출: 키/잔액, JSON 스키마 호환, 한국어 길이와 실제 토큰/비용 확인.
2. 목표 약 30개 사례에서 사실관계·A/B 방향·상한 존중·미정 처리·비난/강요/합의 오판 여부 평가. 구조 검증만으로 통과 처리하지 않는다.
3. 실제 Mongo에서 두 요청 경쟁·예산 CAS·철회 경쟁 확인. 현재 MemoryDatabase 테스트를 실DB 검증으로 보고하지 않는다.
4. 프론트에서 동의 v2/텍스트 렌더링/GET 조회/POST 명시 생성/철회 후 화면 삭제를 연결한다.
5. 승인 후 코드 푸시·배포·운영 활성화. 장애 시 false로 되돌리고 원장/메트릭만 확인한다. 키·원문을 로그로 출력하지 않는다.

## 하단 완료 경로·평가 누적 예산 (2026-09-05)

`POST /meeting/complete`는 명시적 최종 행동에서 답변·동의를 함께 저장하고 AI 해설까지 연결한다.
운영 활성화/유료 호출은 이번 코드 변경에 포함되지 않는다. UI 완료와 법적 검토 완료도 별개다.

추가 환경변수:

| 변수 | 의미 |
| --- | --- |
| `DEEP_MEETING_AI_TOTAL_MICRO_USD` | 평가 전체 예약 상한. 0~5000000, 5000000은 $5 |
| `DEEP_MEETING_AI_PRIOR_MICRO_USD` | 원장 도입 전 평가의 기존 사용/실패/진행 중 예약액을 확인한 보수적 선차감값. 0~총상한 |

두 값은 함께 설정한다. 이전 유료 호출 기록이 있으므로 확인 없이 prior=0으로 시작하지 않는다.
기존 일별 원장, 다른 테스트 스크립트의 호출, 아직 정산되지 않은 시도까지 운영자가 확인한 후 설정한다.
확인할 수 없다면 완료 경로의 유료 생성은 보류한다. 두 값 미설정이어도 답변·동의 저장/기본 결과는 가능하다.
한 값만 있거나 형식/범위가 잘못되면 AI 설정 전체가 비활성으로 처리된다.

원장은 기존 `deep_meeting_budgets`의 `_id=evaluation-total-v1` 단일 문서다. `expiresAt`이 없어 TTL 삭제 대상이 아니다.
세션/계정 ID를 저장하지 않고 방 초기화/만료/서버 재시작과 독립된다. 원장을 지우면 보호가 사라지므로 초기화 대상으로 넣지 않는다.
첫 생성 시 저장한 상한보다 설정을 올려도 한도가 자동 증가하지 않는다. 이전 차감값이 저장된 값과 다르면 신규 예약을 거부한다.
설정을 제거해도 이미 있는 원장은 계속 적용된다. 배포 중 설정이 다른 인스턴스를 혼용하지 말고 일관되게 전환한다.
일별 예약 후 전체 예약을 수행한다. 중간 실패/거절은 보수적으로 예약을 환급하지 않아 실제 호출보다 먼저 한도에 도달할 수 있다.
사용량이 예약의 토큰 상한을 넘으면 해당 날짜와 누적 원장을 모두 halted 처리한다.

기존 수동 POST `/explanation`은 누적 설정/원장이 없는 구형 동작과 호환된다. 누적 설정 도입 이후에는 같은 전체 원장을 따른다.
새 완료 경로에서 유료 자동 연결을 쓰려면 반드시 누적 설정을 먼저 완료한다. 기존 일일 한도·호출 수 한도도 함께 적용된다.
제공자 가격 변경, 앱 외부 API 사용, 세금/환율, 원장 삭제를 포함한 청구서 절대 상한 보장은 아니다.

국외이전/위수탁/제공의 법적 근거와 실제 처리 국가·수령자·보관 조건은 계약/설정과 대조해 운영 전에 검토한다.
동의 v2는 기존 월 분담용 데이터만 허용한다. 확장 동의 v3여도 별도 확장 플래그와 누적 예산이 없으면 외부 전송하지 않는다.
운영 전 합성 사례 품질 승인과 실제 Mongo 경합 검증이 필요하며, 현재 구현 완료가 법적 고지·실운영 승인을 뜻하지 않는다.
