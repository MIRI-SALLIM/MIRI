# F10 대기 화면이 구현되지 않은 F11 CTA를 노출했다

- 작성일: 2026-09-06
- 관련: 이슈 #88, PR #90, 커밋 `078aa3d`

## 무엇이 잘못됐나

F10의 `DeepWaitingPage`가 세션 상태를 성공적으로 불러온 뒤 `다음 단계 보기` 링크를 항상 노출했다. 링크는 `/deep/plan/:sessionId`로 이동하지만 해당 경로는 F11의 `준비 중` placeholder라서, 사용자가 구현되지 않은 다음 단계를 제공되는 기능으로 오인하게 된다.

이 문제는 독립 리뷰가 PR #90의 대기 화면과 F10/F11 단계 경계를 대조하면서 발견했다. 프로덕션 장애나 데이터 손실이 아니라, 병합 전 staged-delivery 경계를 위반한 사용자 노출 결함이다.

## 원인

- **설계적 원인**: F10 완료 조건의 "상대방을 기다리지 않고 시작"을 구현된 다음 화면으로 이동할 수 있다는 의미로 과도하게 해석했다. 계획서가 F10을 세션 생성·초대·참여·상태·철회로 제한하고 F11을 공동 계획으로 분리한 경계를 UI 검토에서 놓쳤다.
- **코드적 원인**: `apps/frontend/src/pages/deep-waiting/ui/DeepWaitingPage.tsx`의 성공 상태 분기에 F11 `/deep/plan/:sessionId` 링크를 추가했고, 대기 페이지 테스트가 그 placeholder 링크의 존재를 기대했다.

## 해결

F10 대기 화면에서 `다음 단계 보기` CTA를 제거하고, 세션 상태 설명과 철회 동작은 그대로 유지했다. 링크 대상을 다른 placeholder로 바꾸지 않고, F11이 구현될 때까지 미완성 기능을 광고하지 않는 가장 작은 변경을 택했다.

## 재발 방지

대기 페이지 회귀 테스트가 성공 상태에서 구현되지 않은 F11 CTA가 존재하지 않음을 단정하도록 바꿨다. 앞으로 단계별 완료 조건을 확인할 때는 링크의 존재만 확인하지 말고 목적지의 구현 상태와 현재 단계의 노출 경계를 함께 검토한다.
