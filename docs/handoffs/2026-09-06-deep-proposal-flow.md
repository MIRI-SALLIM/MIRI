# 딥모드 조정안·기준표 백엔드 인계

2026-09-06 · `codex/deep-money-meeting` 로컬 변경. 이번 작업은 커밋·푸시·배포하지 않았다.
기존 프론트/수동 검증의 미커밋 변경은 보존했다. 프론트 수정은 생성 API 스냅샷/타입에 한정한다.

## 구현된 흐름

1. **가이드 보완**: `GET /meeting/guide`의 reference/personalNeeds와 합의 인식 차이·개인비/저축 확인 질문.
   원래 질문에 받은 값을 활용하며 불변 리포트·계산 버전·기존 AI 근거/동의 범위는 유지한다.
2. **조정안 비교**: `POST /meeting/preview`. 서버 원안과 조정안의 분담 공백/초과/변화량을 계산한다.
   공동비 200만/A 80만/B 80만 → 공백 40만, A 100만/B 80만 → 20만, 예산 180만 → 0.
   마지막 안은 계획 변경 확인이 필요하고 주거 공백/월 적자/목표 부족은 그대로다.
3. **우리 돈의 기준표**: `GET /meeting/standards`. 현재 기준표를 양측 확인/제안/보류로 구분하고
   담당자·시작월·납부일·예외·재검토일·확인 버전을 보존한다. 기존 agreement 저장/수정/확인 절차를 사용한다.

## 안전·연결 경계

- 미리보기/요약은 저장·합의·유료 AI 호출을 하지 않는다. Kakao 로그인과 기존 AI 완료 흐름은 변경하지 않았다.
- 양측 재무 공유 없이 민감 입력을 노출하지 않는다. 추가 답변 상한은 양측 같은 버전의 공유 동의가 있어야 보인다.
  AI 동의는 필요 없고, 공유 철회/버전 혼합이면 상한을 숨긴다. 상한 이내도 실제 지급 능력이나 동의의 판정은 아니다.
- 미정/0/추정 구분, 안전 정수 합계, 같은 월/항목 비교, 최신 round/plan/report 및 조회 도중 철회 검사를 유지한다.
- 예산/항목/시작월 변경은 `revise_plan`, 완성된 조정안의 원안만 미정이면 `revise_inputs`로 새 라운드 확인을 안내한다.
  조정안 자체 미정은 `complete_numbers`. 기존 월 분담 기준표가 있으면 `review_agreements`로 기존 안 수정을 먼저 안내한다.
- 개인비/저축 희망액을 월 잔액에서 중복 차감하지 않는다. 같은 주제의 기준표가 있다고 모든 질문을 자동 해결 처리하지 않는다.
- 기준표 수정은 양쪽 확인을 해제한다. 초안의 기본 null/빈 값으로 기존 납부일·예외를 덮어쓰지 않도록 프론트 문서에 명시했다.

## 검증

- 새 통합 테스트 **18개** 포함, 관련 v3/meeting/AI/OpenAPI 테스트 **236 passed**, 기존 Starlette 경고 1개.
- 변경 Python 6개 파일 Ruff/mypy 통과. 프론트 `tsc --noEmit` 통과.
- OpenAPI 연속 생성 결정성 통과, backend/frontend/frontend-handoff 세 JSON 동일, 프론트 타입 재생성 완료.
- `git diff --check` 통과. 별도 읽기 전용 리뷰에서 원안 미정일 때 숫자 보완 안내가 반복되는 문제를 재현한 뒤
  `revise_inputs` 분기와 회귀 테스트로 수정했다. 다른 중대/중요 문제는 보고되지 않았다.
- 테스트는 메모리 DB 통합 및 로컬 타입/계약 검증이다. 운영 Mongo 동시성·배포 프론트 E2E를 검증한 것은 아니다.
