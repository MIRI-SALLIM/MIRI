# 스스로 만든 문제를 스스로 막는 장치를 추가할 뻔했다

- 작성일: 2026-09-05
- 관련: 이슈 #53, PR #60, 커밋 `41f4283`

## 무엇이 잘못됐나

이슈 #53은 "창 포커스 refetch가 저장되지 않은 로컬 입력을 덮어쓴다"였고, 본문이 세 방향을 제시했다.

1. `refetchOnWindowFocus: false`를 입력 조회에 준다
2. 자동저장 성공 시 `setQueryData`로 캐시를 갱신한다
3. hydration을 세션당 한 번으로 제한한다

구현자가 **1과 2를 넣고, 2가 만든 문제를 막기 위해 3의 변형(ref marker + 동일 입력 skip)까지** 넣었다. `LightFormPage.tsx`에 51줄이 늘었다.

코디네이터가 2와 3을 제거하고 테스트를 돌렸다.

```
× updates the cached input after autosave succeeds
× keeps a newer local edit when an earlier autosave resolves
Tests  2 failed | 17 passed (19)
```

**실패한 둘은 옵션 2 때문에 존재하는 테스트였다.** 이슈가 보고한 결함의 회귀 테스트는 옵션 1만으로 전부 통과했다.

## 원인

**설계적 원인**: 논증이 순환했다.

| | 역할 |
| --- | --- |
| 옵션 1 | 보고된 결함을 고친다 |
| 옵션 2 | 그 위에 **새 덮어쓰기 경로를 만든다** — 저장 성공이 `inputQuery.data`를 바꾸면 hydration effect가 다시 돌고, 저장 요청 이후 사용자가 더 입력했다면 그것이 지워진다 |
| 옵션 3 | **옵션 2가 만든 경로를 막는다** |

옵션 2를 넣지 않으면 옵션 3도 필요 없다. 그리고 옵션 2의 이득은 애초에 없었다 — 저장 성공과 다음 마운트 사이에 그 캐시 항목을 읽는 소비자가 없고(409 경로의 `getLightInput`은 캐시를 거치지 않는다), `refetchOnMount` 기본값이 true라 다음 마운트에서 어차피 서버를 다시 조회한다.

**이슈가 세 방향을 제시했다는 것이 셋 다 하라는 뜻으로 읽혔다.** 이슈 본문은 "1번과 2번을 함께 하는 것이 나아 보인다"고 적었는데, 그 판단 자체가 옵션 1이 refetch를 끈다는 사실과 맞지 않았다 — 끈 뒤에는 옵션 2가 대비하는 refetch가 없다.

**테스트가 그 순환을 감췄다.** 옵션 2를 넣으면 옵션 2를 검증하는 테스트가 생기고, 그것이 통과하니 전체가 정당해 보인다. **어떤 테스트가 무엇 때문에 존재하는지**를 따로 묻지 않으면 드러나지 않는다.

## 해결

옵션 2와 3, 그리고 옵션 2 때문에 존재하던 테스트 2개를 제거했다. **`LightFormPage.tsx` 순증가가 51줄에서 2줄이 됐다.**

```ts
refetchOnWindowFocus: false,
refetchOnReconnect: false,
```

같은 화면의 상태 조회에는 두 플래그가 이미 명시되어 있었다. **입력 조회에 같은 처리가 필요하다는 것은 새 판단이 아니라 바로 옆에서 내려진 판단이 여기에 적용되지 않았던 것**이다.

제거를 지시하기 전에 **옵션 2의 실제 이득을 조사하라**고 요구했다. 근거 없이 유지하지도, 조사 없이 제거하지도 않게 하기 위해서다.

이 파일은 #44와 #54가 두 번 단순화한 곳이다. 51줄이 다시 쌓이면 그 정리가 무효가 된다.

## 재발 방지

**변경을 제거해보는 것을 검증 절차에 넣었다.** 구현이 여러 부분으로 이뤄져 있으면 각 부분을 빼고 테스트를 돌려 **무엇이 실패하는지** 본다. 실패하는 것이 그 부분 때문에 생긴 테스트뿐이면 그 부분은 자기 자신을 정당화하고 있다.

**앞으로 의심할 것**: 방어 장치를 추가할 때 "이것이 막는 문제가 이 변경 이전에도 있었는가"를 묻는다. 없었다면 그 문제를 만든 것이 같은 변경의 다른 부분이고, 둘 다 빼는 것이 답일 수 있다.

이슈가 제시하는 방향들은 **선택지이지 체크리스트가 아니다.** 여럿을 채택할 때는 그것들이 서로 독립인지, 하나가 다른 하나를 필요하게 만드는지 확인한다.
