# 우리 돈의 기준회의 — AI 해설 제품 설계

2026-09-04. 사용자가 채팅에서 검토한 최종안을 승인하고 문서화·구현 시작을 요청했다.
기준 코드: develop의 PR #40 병합(a62efe9). 이 문서는 제품 목표이며 구현 완료 증거는 아니다.

## 1. 목적과 성공 기준

미리살림은 두 사람이 함께 살 돈의 기준을 만드는 서비스다. AI 결과의 끝은 긴 설명이 아니라
`아직 해결하지 못한 문제 → 조정할 조건 → 선택지 → 양측이 확인한 기준 또는 보류`다.
비난은 제거하되, 의사결정에 필요한 불편한 사실은 제거하지 않는다.

- 숫자 계산, 문제 우선순위, 권한, 실제 합의 여부는 서버가 결정한다.
- AI는 이미 공개가 허용된 근거와 명시적인 답변을 연결해 해설·대화 질문을 작성한다.
- 제안 금액, 본인이 밝힌 조정 상한, 계산상 공백 해소, 지급 능력, 양측 합의를 구분한다.
- 모르는 값은 0원이 아니다. 답변 차이로 성격·의도·관계의 좋고 나쁨을 판정하지 않는다.
- 기존 Light/v2/v3 동작과 AI 없이 끝까지 사용할 수 있는 템플릿 경로를 유지한다.

## 2. 사용자 경험

1. 기존 공동 리포트가 준비된 뒤 서버가 실제 쟁점을 보여준다. 공개 전에는 상대 입력에 따라
   질문 수·순서·대기 응답이 달라지지 않는다.
2. 필요한 경우에만 각자 `우선 제안 / 내가 제시할 상한 / 아직 모름`을 선택한다.
   조정 가능한 상한은 선택 입력이며 지급 능력 검증으로 취급하지 않는다.
3. 양측의 명시적 공개·AI 동의와 필요한 답변이 준비되면 AI를 한 번 호출한다.
   중심 쟁점 하나를 설명하고, 최대 세 개의 짧은 카드를 제공한다.
4. 사용자가 예산·A/B 분담액을 바꾸면 별도의 작은 계산 함수가 비교한다. AI를 다시 호출하지 않는다.
5. 선택한 안을 기존 합의 입력에 연결한다. 같은 버전의 양측 확인 전에는 합의로 표시하지 않는다.

예시: 공동 예산 200만 원, A/B 제안 80/80만 원이면 공백은 40만 원이다.
추가 질문에서 A는 100만 원, B는 80만 원을 이번 논의의 상한으로 답했다면 합계는 180만 원이다.
예산 180만 원·분담 100/80만 원은 계산상 공백이 없지만, 지출 절감 가능성·지급 능력·공정성·합의는
확인된 것이 아니다. 기존 데이터만으로 상한을 추정하거나 자동으로 이 안을 선택하지 않는다.

## 3. 단계별 범위

| 단계 | 산출물 | 현재 요청에서의 실행 범위 |
| --- | --- | --- |
| A | 순수 함수: 최소 근거 패킷, 월 분담안 비교, 생성 응답 구조·근거 참조 검사 | 이번 실행 계획의 전부 |
| B | 추가 질문·답변 저장, 별도 AI 동의, 서버 권한 확인, 생성·조회 API의 저장소 경계 | A 검토 이후의 독립 실행 단계 |
| C | OpenAI 호출, 캐시·동시 생성 잠금·비용 제한·타임아웃·템플릿 대체 | API 키·유료 호출 승인 후 실호출 검증 |
| D | 프론트 전달 계약·화면 연결·합성 사례 평가·운영 검증 | 백엔드 계약과 화면 준비 후 |

A는 기존 공개 리포트의 월 공동예산·분담·상대 기대만 다룬다. 주거 재원 시점, 목표, 가치관,
추가 질문의 이유, 상한, 합의 예외의 AI 해설은 이 단계에서 전송하지 않는다.
전체 제품의 세부 API/저장소 실행 계획은 각 단계 착수 때 현재 코드를 기준으로 별도 확정한다.

## 4. A단계의 구현 계약

### 근거 투영

`deep/meeting/brief.py`의 `build_brief(result, permissions)`는 서버가 조회한 ready 결과만 받는다.
호출자가 서버 상태에서 도출한 양측 AI 동의 및 양측 재무 공개 여부를 전달해야 한다.
이 순수 함수는 인증 또는 실제 동의 저장소를 대신하지 않는다. 클라이언트 JSON을 직접 연결하지 않는다.

전송 허용 목록: round, planVersion, 공통 범위·시작월, 공동예산, A/B 분담 제안,
분담 합계·공백·초과액, 상대 기대와 제안의 차이, 현재 월 분담 합의 상태의 제한된 enum,
계산 블록의 가정 존재 여부, 코드가 만든 쟁점 ID와 근거 ID.

금지 목록: 이름, 계정/세션/보고서/초대 ID, 토큰, 자산·부채 원장, 자유서술, 기존 observation/question,
limitations의 임의 문자열, 원본 assumptions/missingFields 문자열, 원본 답변 전체, 합의 원문.
허용 목록 외 필드는 패킷에 복사하지 않는다. A/B 표시는 익명성의 보장이 아니다.

금액은 엄격한 정수이고 절댓값이 2**53-1 이하여야 한다. bool/float/string을 금액으로 변환하지 않는다.
블록의 명시적 reason(공개 거부·범위 초과 등) 또는 data 부재는 재사용하지 않는다.
기존 v3 엔진은 일부 금액 미정으로 공백을 계산할 수 없어도 known data를 유지한 채 unavailable을 반환한다.
이 경우에만 미정 필드와 missingFields가 일치하는지 확인한 후 알려진 값만 투영하며 공백은 미정으로 남긴다.
원인 불명의 unavailable은 거부한다. 버전·필수 형식·산술 관계가
잘못된 경우 MEETING_EVIDENCE_INVALID로 중단하며 오류에 원문을 넣지 않는다.
권한 부족은 패킷을 만들기 전에 중단한다. 이 단계에서는 외부 송신 코드 자체가 없다.

### 분담안 비교

`deep/meeting/comparison.py`의 `compare_budgets(baseline, proposal)`는 월 공동예산과 A/B 분담만 비교한다.
포함 항목 및 시작월이 다르면 scope_or_month_mismatch로 비교를 중단한다. 항목의 순서는 의미가 없다.
한 값이라도 미정이면 해당 안의 공백을 None으로 남긴다. 합계 안전 정수 범위를 넘으면 거부한다.
0원은 유효한 입력이며, 초과 분담은 음수 부족액이 아니라 별도 excess로 반환한다.
결과의 basis는 calculation_only_not_affordability_or_agreement로 고정한다.
실제 저장된 계획·합의는 변경하지 않는다.

### 생성 응답 계약

`deep/meeting/explanation.py`의 `validate_grounding(draft, brief)`는 다음을 검사한다.

- 응답은 cards 배열(1~3개). 카드마다 issueId, factIds, explanation, question만 허용한다.
- issueId는 패킷에 있는 쟁점이어야 하며 중복 카드는 금지한다.
- factIds는 해당 쟁점에 연결된 근거여야 한다. 근거가 있는 쟁점은 최소 한 개를 참조해야 한다.
- explanation은 1~300자, question은 1~160자. 공백뿐인 문장 및 숫자 문자를 거부한다.
- 금액은 서버가 근거 칩으로 표시한다. 원시 AI 문장을 HTML로 렌더링하지 않는다.

숫자 문자 검사와 JSON/근거 검사는 의미적 진실성을 증명하지 않는다. 예를 들어 한글로 쓴 잘못된 금액,
근거와 모순된 표현, 비난은 별도의 사례 평가와 운영 검증 대상이다. A단계 검사만으로 사용자 노출을
허용하거나 '환각 방지 완료'로 표시하지 않는다.

## 5. B~D단계의 필수 안전 조건

### B단계 상세 계약 (2026-09-04 후속 진행)

- 기존 공동 리포트가 ready이고 양측 재무 공개가 유효한 v3 세션만 추가 질문을 사용한다.
- 질문은 고정 두 항목이다. `contributionMeaning`은 initialProposal/selfReportedLimit/unknown,
  `adjustableMonthlyWon`은 늘릴 수 있는 월 분담 상한의 선택 입력이다. 지급 능력은 검증하지 않는다.
  원래 제안이 미정이면 의미는 unknown만 허용한다. 추가 상한은 initialProposal이고 원래 제안 이상일 때만 받는다.
- 본인 답변은 본인 GET에만 포함한다. 추가 답변의 상대 공유와 OpenAI 외부 처리를 별도 bool로 받는다.
  외부 처리만 동의하고 상대 공유를 거절하는 조합은 거부한다. 둘 다 기본 미동의다.
- 동의 문구 버전은 `money-meeting-consent-v1`이다. 현재 구현은 동의 기록만 저장하며 실제 전송하지 않는다.
  실제 외부 전송 활성화 전 공급자 보관/처리 안내와 실운영 동의를 재검토한다. 문구 변경 시 재동의를 받는다.
- 각 참여자의 revision은 답변 저장·동의 변경·철회 때 증가한다. stale revision/round/plan 요청은 409다.
  답변을 수정하면 해당 참여자의 동의가 지워진다. 상대의 동의는 상대 자신의 변경 없는 답변에 대한 동의로 남는다.
- 양측 현재 답변 및 공유·AI 동의가 모두 있어야 준비 context를 읽는다. 그 전에는 waiting만 제공한다.
  질문/본인 조회에 상대 답변·동의 상태·완료 여부는 넣지 않는다.
- DELETE 본인 동의는 stale 입력 버전을 요구하지 않는다. 이미 철회했다면 추가 변경 없이 성공한다.
  새 round 및 withdraw는 meeting을 지운다. 심사용 방 reset/계정 삭제/만료는 기존 접근 차단과 TTL 정책을 따른다.
- 저장은 세션 단일 문서 CAS를 사용한다. context는 리포트 조회 뒤 현재 문서 버전을 재검사한다.
  현재 합의 상태는 기존 리포트 API와 같은 조회 시점의 snapshot이며 C단계 생성 저장 전에는 재검증해야 한다.
- B의 context는 AI 생성 결과가 아니다. `providerStatus=not_connected`를 명시하고 API 비용은 발생하지 않는다.

### 후속 생성/운영 조건

- 상대 공개 동의와 외부 AI 전송 동의를 분리한다. 새 확인 답변도 공개 범위를 명시하고 양측 동의를 받는다.
- 생성 전·저장 직전·조회 시마다 참여자 권한, 만료, 철회, round/plan/동의 버전을 재확인한다.
- 리포트·답변·합의·프롬프트·모델 버전을 캐시 키에 포함한다. 버전이 바뀌면 이전 해설을 현재처럼 표시하지 않는다.
- 한쪽이 동의를 철회하거나 방을 초기화하면 관련 패킷/해설 접근을 차단하고 기존 정리 정책에 연결한다.
- 외부 전송 전 동의 철회는 차단할 수 있지만, 이미 전송된 요청을 소급해서 회수했다고 약속하지 않는다.
- 같은 커플·버전의 동시 요청은 한 번만 생성한다. 서버 재시작·잠금 만료·중복 완료 저장을 다룬다.
- 타임아웃·429·5xx·거부·잘린 출력·검증 실패에는 원문 노출 없이 템플릿으로 대체한다.
- 불완전한 AI 문장을 스트리밍으로 먼저 공개하지 않는다. 재시도도 총 호출/비용 한도에 포함한다.
- AI 제안은 자동 합의 저장이나 확인이 아니다. 필요한 필드는 사용자가 채우고 양측이 확인한다.

## 6. 모델·비용·운영

첫 후보: GPT-5.4 mini, Responses API, 공식 Python SDK, 구조화 출력.
대안 GPT-4.1 mini는 같은 합성 사례를 비교하여 품질이 충분할 때 선택한다. 초기 자동 다중 모델 전환,
별도 GPU·학습·벡터 DB·Redis·Celery·웹 검색 도구는 도입하지 않는다.

목표는 보고서 버전당 한 번 생성하고 재조회 시 재사용하는 것이다. 필요한 데이터만 전송하고
입력(지시문·스키마 포함) 1,500토큰·출력 800토큰은 목표 예산이지 보장된 사용량이 아니다.
2026-09-04 공식 단가로 GPT-5.4 mini는 입력 $0.75/1M, 출력 $4.50/1M이다.
위 가정에서는 1회 $0.004725, 1,000회 $4.725이며 세금·환율·재시도·추가 과금 출력은 별도다.

키는 백엔드 비밀 변수로만 관리한다. 실제 호출 전 사용자 승인을 받는다. 공급자 대시보드 알림만을
하드 한도로 믿지 않고 서버에서 동시 요청을 고려한 호출/토큰 예산 예약 및 한도 도달 차단을 구현한다.
`store: false`는 공급자의 모든 보관을 없앤다는 의미가 아니다. 기본 API 데이터 학습 미사용과
일반 악용 방지 로그 보관은 구분해 안내한다. 현재 단계는 실데이터를 외부로 전송하지 않는다.

## 7. 검증 및 출시 경계

C단계 구현 결정: [생성 계획](../plans/2026-09-04-deep-money-meeting-generation.md).
비전송 안내였던 동의 v1은 외부 처리 동의 v2로 재동의한다. GET은 조회만, POST만 명시 생성이다.
하루 예산은 보수적 선예약으로 제한하며 과금 여부가 불확실한 시도는 자동 재시도하지 않는다.
모델은 GPT-5.4 mini 스냅샷 고정, 기본 비활성이다. 정책·화면·실제 모델 품질은 완료로 간주하지 않는다.

A단계: 실제 v3 계산기를 사용한 합성 리포트로 40만 원 공백과 A/B 각각의 40만 원 기대 차이를
