# Deep v3 입력 저장·분담 질문·공동 리포트 연결

2026-09-03. 기존 `fix/gate2-openapi-contract` 작업 트리에서 구현. 이 인계 자체는 커밋·푸시·배포를 의미하지 않는다.

## 완료 범위

- `/api/v1/deep/v3` opt-in 세션. 질문 deep-v3, 규칙 deep-rules-v2, 카피 deep-copy-ko-v2, 동의 deep-sharing-v2를 고정한다. v2·Light 기본 경로는 유지한다.
- 새 재원/상환 이벤트/분담 의사/상대 기대/개인 최소액/수용 조건 저장. 기존 자산·부채와 ID 연결, 배정 이중 원장 차단, revision·planVersion 충돌 보호.
- 가치관10문항 + C1~C6 + 본인만 사용하는 조건부 질문. 상대 비공개 초안을 질문 분기에 사용하지 않는다.
- 양측 제출·동일 계획 확인 후 불변 공동 리포트. 재무/가치관 동의 별도 게이트. 새 재원 날짜별 공백, 월 참고 예산, 목표, 분담 공백·기대 차이·조건 이슈 연결.
- 구조화한 기준 제안·양측 확인·편집·보류. 최신 합의 상태는 report 외부 operatingStatus로 반환. `commonScope`와 시작월이 일치할 때만 전체 예산 대비 비교. 복수의 합의된 월 분담안은 conflicting.
- 재작성은 버전을 유지하고 동의를 다시 받는다. 서로 다른 버전의 세션 접근/초대 수락 차단. 철회는 종료 후 정리 재시도도 가능하다.
- 프론트·백엔드 OpenAPI 동기화, 검증 가능한 가상 요청 예제 추가.

## 계산 경계와 리뷰 수정

현재 월 지출과 상환 후 계획 지출을 분리한다. v3 기본 변동비 계수는1.0이며 기존 v2의0.85를 소급 변경하지 않았다. 부분 상환 후 월 납입액 미정, 신규 개인 차입의 월 조건 부족, 목표 재원의 상환액·날짜 미정은 확정값을 만들지 않는다. 공동 집값·대출은 한 번만 합산하며 개인 source/debt ID는 A/B namespace로 충돌을 피한다. 합산 안전 정수 범위를 넘으면 계산을 숨긴다.

독립 리뷰에서 발견한 합의 범위·시작월 비교 누락, 월 적자 카드의 우선순위/기준일 누락, 철회 정리 재시도 차단을 수정하고 회귀 테스트를 추가했다. 이전 질문 조회가 불필요하게 DB에 접근하던 회귀도 수정했다. 카드 최대3개와 전체 issues 목록은 분리한다.

이번 작업은 새 저장→질문→공동 결과 흐름이다. 전체 F/P/U 재무 질문 UI, 모든 조건의 자동 비교·최적화, 별도 what-if/장기 월별 재계산, AI/정책 매칭, 프론트 화면·실배포를 완료한 것으로 해석하면 안 된다. 상세 개인/공동 비용 재분류는 현재 입력만으로 추정하지 않는다. 개인비 최소액은 자동 추가 지출로 차감하지 않는다.

## 검증

최종 검증 결과는 아래에 기록한다. 실Mongo 테스트는 기존 안전한 격리 DB 도우미를 사용하며 앱 Atlas URI를 읽지 않는다. 환경이 없으면 명시적으로 skip한다. 실제 Mongo의 동시 제출·단일 리포트·동시 확인·편집 초기화·철회 정리 검증 사례를 추가했다.

- 최종 `scripts/test_local.py -q`: **386 passed / 17 skipped / 11 warnings** (36.60초). 환경 의존 검증 17건은 수행하지 않았으며 실Mongo/HTTPS 실검증 완료로 간주하지 않는다.
- Ruff 전체 통과, mypy 121개 파일 통과. 경고는 기존 Starlette 테스트/422 상수 사용 중단 예고다.
- OpenAPI 두 번 생성 결과 일치, 프론트·백엔드 스냅샷 SHA256 일치. `git diff --check` 통과.
- 독립 최종 재검토: 검토 범위 내 Critical/Important 잔여 없음, 리뷰어의 대상 테스트 32개 통과.
- 운영 DB·Railway·카카오 설정·실제 사용자 계정 변경 없음.
