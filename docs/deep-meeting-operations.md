# 우리 돈의 기준회의 — AI 운영 설정

2026-09-04. 코드는 로컬 구현, 모의 API 검증 상태다. 이 문서는 운영 활성화 완료 기록이 아니다.

후속 상태: [v2 가상 3건 실호출](handoffs/2026-09-04-deep-money-meeting-v2-live-smoke.md)에서 연결·상한 반영·미정 처리를 확인했다. 이후 중복 질문 지시를 보완한 현재 프롬프트는 `money-meeting-v3-known-answers`이며 실모델 재호출은 하지 않았다. 최신 운영 준비 상태는 [배포 준비 인계](handoffs/2026-09-04-deep-meeting-release-preparation.md)를 따른다.

## Railway 설정

백엔드 서비스 Variables에만 설정한다. 프론트 번들·Git·대화에 키를 넣지 않는다.

| 변수 | 기본/의미 |
| --- | --- |
| OPENAI_API_KEY | 해당 OpenAI 프로젝트의 키. 등록만으로 AI가 켜지지 않음 |
| DEEP_MEETING_AI_ENABLED | false. 품질·권한·비용 검증 후에만 true |
| DEEP_MEETING_AI_DAILY_MICRO_USD | 250000 = 모델 비용 예약 $0.25/UTC 일, 세금 별도 |
| DEEP_MEETING_AI_DAILY_CALLS | 20 = 하루 생성 시도 최대치. 금액 한도와 함께 적용 |

기존 DEEP_MODE_ENABLED·계정 인증·DB 설정도 유효해야 한다. 잘못된 한도 설정은 AI 비활성으로 처리한다.
금액 설정 허용 범위는 0~5000000, 횟수는 0~200이다. 0은 추가 생성 차단이다.
비활성 플래그는 저장된 AI 해설 노출도 멈추고 기본 해설로 전환한다. 이미 외부 전송 중인 요청을 회수하지는 못한다.

## 호출·비용 방식

- 모델은 `gpt-5.4-mini-2026-03-17` 고정, Responses API, reasoning none, 출력 800토큰, 총 20초, SDK 재시도 0회.
- 클라이언트 GET은 모델 호출을 하지 않는다. 같은 컨텍스트의 동시 POST/반복 POST는 시도 원장으로 중복을 막는다.
- 일일 한도는 서비스 공용 Mongo 원장에서 선예약한다. 현재 한 요청당 **$0.018672**를 예약하므로 기본 금액 한도에서는 최대 **13회**까지 허용한다.
- 이 금액은 예상 실제 요금이 아니다. 요청 JSON UTF-8 최대 16000바이트에 입력 여유 4096토큰과 출력 상한을 적용한 보수적 예약이다. 실제 입력 1500·출력 800토큰이면 모델 요금 예시는 약 $0.004725다.
- 실패/타임아웃/낮은 실제 사용량이어도 예약을 환급하지 않는다. 사용량이 예약 가정을 벗어나면 당일 원장을 halted로 닫는다.
- 현재 공식 단가(입력 $0.75/백만, 출력 $4.50/백만)를 고정 계산한 서버의 호출 허용 한도다. 가격 변화·숨은 토큰 산정·별도 프로젝트 호출·세금까지 포함한 청구서의 절대 상한은 아니다.
- OpenAI 대시보드의 지출/잔액도 확인한다. 실제 단가/최대 입력을 검증한 뒤 운영 예약을 조정한다. 사용자의 다른 API 호출은 이 원장을 거치지 않는다.

## 저장과 철회

- `deep_sessions.meeting.generation`: 현재 컨텍스트의 검증된 카드. 세션 TTL, 답변/동의 변경·탈퇴·새 round 시 기존 수명 규칙을 따른다.
- `deep_meeting_attempts`: 원문 없는 세션 ID·컨텍스트 해시·시도 상태/기한·성공 사용량. 세션 만료 시 TTL, 탈퇴 시 삭제. 원장을 수동 삭제하면 중복 과금 방지가 무너질 수 있다.
- `deep_meeting_budgets`: UTC 일별 예약액/횟수/halted. 개인정보 없음, 약 35일 TTL. 재시작해도 유지한다. 예산 원장을 초기화해서 한도를 우회하지 않는다.
- 양측 동의 v2가 필요하다. v1은 이전 비전송 안내이므로 실전송 허가로 사용하지 않는다.
- `store=false`로 호출하지만 공급자의 남용 방지 보관까지 없는 것은 아니다. API 데이터는 기본 학습에 쓰이지 않는다. 실출시 전 개인정보 안내/처리 정책을 별도로 검토한다.
- 전송 직전·저장 전후·조회 시 현재 권한과 근거를 재검사한다. 전송 직후 철회된 데이터는 외부에서 회수할 수 없으며 결과 저장/제공을 막는다.
- 프로세스 중단이나 완료 여부가 모호한 타임아웃은 같은 컨텍스트를 다시 호출하지 않는다. 기한 지난 응답도 저장하지 않는다. 새 컨텍스트까지 기본 해설을 사용한다.

## 활성화 전 남은 검증

1. 승인받은 합성 사례로 실제 API 소량 호출: 키/잔액, JSON 스키마 호환, 한국어 길이와 실제 토큰/비용 확인.
2. 목표 약 30개 사례에서 사실관계·A/B 방향·상한 존중·미정 처리·비난/강요/합의 오판 여부 평가. 구조 검증만으로 통과 처리하지 않는다.
3. 실제 Mongo에서 두 요청 경쟁·예산 CAS·철회 경쟁 확인. 현재 MemoryDatabase 테스트를 실DB 검증으로 보고하지 않는다.
4. 프론트에서 동의 v2/텍스트 렌더링/GET 조회/POST 명시 생성/철회 후 화면 삭제를 연결한다.
5. 승인 후 코드 푸시·배포·운영 활성화. 장애 시 false로 되돌리고 원장/메트릭만 확인한다. 키·원문을 로그로 출력하지 않는다.
