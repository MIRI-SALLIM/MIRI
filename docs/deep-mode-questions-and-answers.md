# 미리살림 딥모드 질문·답변 정리

> 기준일: 2026-09-06
>
> 범위: 현재 백엔드 `deep-v3` 계약과 질문 생성 코드
>
> 목적: 기획·프론트·테스트에서 실제 질문 문구와 허용 답변을 한곳에서 확인하기 위한 문서

## 1. 먼저 알아둘 점

- 이 문서는 **실제 사용자가 입력한 답변**이 아니라, 현재 딥모드가 받는 **질문과 답변 형식·선택지**를 정리한다.
- `정확히 앎(known)`, `모름(unknown)`, `공개하지 않음(withheld)`을 구분한다. `0원`은 `known + 0`이며 모름과 다르다.
- 개인 메모는 질문·영역별로 선택 입력할 수 있지만 자동으로 상대에게 공유하지 않는다.
- D1~D10, C1~C6, P8, U4, 공동 확인 질문은 서버에 고정되어 있다.
- 재무 입력 화면의 짧은 제목과 배치는 프론트가 정할 수 있지만, 아래 데이터와 상태 구분은 백엔드 계약을 따라야 한다.
- 공동 리포트와 AI 해설 질문은 두 사람의 입력에 따라 일부만 나타난다. AI는 서버가 계산한 사실을 바꾸거나 새로운 금액을 만들지 않는다.

## 2. 공통 답변 형식

### 2.1 금액

| 화면 표현 | 서버 값 | 의미 |
|---|---|---|
| 정확히 앎 | `status: known`, `precision: exact`, `value: 금액` | 정확한 원 단위 금액 |
| 대략 앎 | `status: known`, `precision: estimate`, `value: 금액` | 추정 원 단위 금액 |
| 모름 | `status: unknown`, `value: null` | 계산에서 0원으로 취급하지 않음 |
| 공개하지 않음 | `status: withheld`, `value: null` | 계산·공유에서 제외 |
| 0원 | `status: known`, `value: 0` | 실제로 금액이 없다는 명시적 답 |

### 2.2 가치관 척도

| 답 | 값 |
|---|---:|
| 왼쪽에 매우 가까움 | 1 |
| 왼쪽에 조금 가까움 | 2 |
| 중간 | 3 |
| 오른쪽에 조금 가까움 | 4 |
| 오른쪽에 매우 가까움 | 5 |
| 건너뛰기 | 답변 `null` + `skippedQuestionIds`에 문항 ID 저장 |

`중간(3)`은 모름이 아니다. D2·D7·D8은 분석할 때 방향을 반대로 보정하지만 사용자는 위 척도대로 답한다.

## 3. 가치관 질문 D1~D10

아래 질문과 좌우 선택지는 `apps/backend/config/deep_questions.v3.json`의 원문이다. 영역명은 이해하기 쉽게 한국어로 표시했다.

| ID | 영역 | 질문 | 왼쪽(1) | 오른쪽(5) |
|---|---|---|---|---|
| D1 | 저축 | 쓰고 남은 돈을 저축한다 ↔ 저축할 돈을 먼저 떼어 둔다 | 쓰고 남은 돈을 저축한다 | 저축할 돈을 먼저 떼어 둔다 |
| D2 | 저축 | 목표 금액과 시기를 정해서 모은다 ↔ 상황에 따라 금액과 시기를 조정한다 | 목표 금액과 시기를 정해서 모은다 | 상황에 따라 금액과 시기를 조정한다 |
| D3 | 소비 | 원하는 것이 생기면 빠르게 구매한다 ↔ 충분히 비교하고 고민한 뒤 구매한다 | 원하는 것이 생기면 빠르게 구매한다 | 충분히 비교하고 고민한 뒤 구매한다 |
| D4 | 소비 | 경조사·선물에는 넉넉히 쓰고 싶다 ↔ 정한 예산 안에서 최소한으로 쓰고 싶다 | 경조사·선물에는 넉넉히 쓰고 싶다 | 정한 예산 안에서 최소한으로 쓰고 싶다 |
| D5 | 투자 | 손실 가능성이 있어도 높은 수익을 추구한다 ↔ 수익이 적더라도 원금 보존을 우선한다 | 손실 가능성이 있어도 높은 수익을 추구한다 | 수익이 적더라도 원금 보존을 우선한다 |
| D6 | 부채 | 필요하면 대출을 활용할 수 있다 ↔ 대출은 최대한 피하고 싶다 | 필요하면 대출을 활용할 수 있다 | 대출은 최대한 피하고 싶다 |
| D7 | 공동관리 | 함께 살면 수입과 지출을 통합 관리하고 싶다 ↔ 각자 관리하고 공동비만 분담하고 싶다 | 함께 살면 수입과 지출을 통합 관리하고 싶다 | 각자 관리하고 공동비만 분담하고 싶다 |
| D8 | 공동관리 | 개인 지출 내역까지 서로 공유하고 싶다 ↔ 개인 지출은 각자의 영역으로 두고 싶다 | 개인 지출 내역까지 서로 공유하고 싶다 | 개인 지출은 각자의 영역으로 두고 싶다 |
| D9 | 투자 | 여유자금이 생기면 투자할 곳부터 알아본다 ↔ 일단 예적금에 두고 생각한다 | 여유자금이 생기면 투자할 곳부터 알아본다 | 일단 예적금에 두고 생각한다 |
| D10 | 부채 | 큰 지출에는 대출을 이용하는 방법도 고려한다 ↔ 지금 가진 돈 안에서 해결한다 | 큰 지출에는 대출을 이용하는 방법도 고려한다 | 지금 가진 돈 안에서 해결한다 |

추가 답변:

- `importantAreas`: 이번에 꼭 이야기하고 싶은 영역을 최대 2개 선택한다. 선택지는 저축·소비·투자·부채·공동관리다.
- `contextNotes`: 문항 또는 영역에 대한 개인 메모다. 문항별 최대 300자이며 자동 공유하지 않는다.

## 4. 각자의 재무 현황 질문

아래는 현재 `deep-input-v3`가 받는 입력이다. 화면 문구는 프론트에서 다듬을 수 있지만 답의 의미는 유지해야 한다.

### 4.1 생활과 소득

| 질문 | 답변 형식 |
|---|---|
| 지금 두 분은 함께 살고 있나요? | 예 / 아니요 / 아직 답하기 어려움(`null`) |
| 세후 월 소득은 얼마인가요? | 금액 상태 + 금액, 기준월(선택) |
| 연간 세후 상여금이 있나요? | 금액 상태 + 금액 |
| 월 소득에 상여금을 이미 나눠 넣었나요? | 예 / 아니요 |
| 상여금은 몇 월에 들어오나요? | 1~12월 또는 미입력 |

### 4.2 월 지출

| 질문 묶음 | 현재 항목 | 답변 형식 |
|---|---|---|
| 매달 고정으로 나가는 돈은 얼마인가요? | 통신(`communication`), 보험(`insurance`), 구독(`subscriptions`), 가족 지원(`familySupport`), 기타(`other`) | 항목별 금액 상태 + 금액 |
| 매달 달라지는 지출은 얼마인가요? | 식비(`food`), 교통(`transport`), 쇼핑(`shopping`), 여가(`leisure`), 기타(`other`) | 항목별 금액 상태 + 금액 |
| 현재 집에 매달 내는 주거비는 얼마인가요? | 현재 본인 부담 주거비 | 금액 상태 + 금액 |

### 4.3 부채

| 질문 | 답변 형식 |
|---|---|
| 현재 갚아야 할 돈이 있나요? | 전체 상태: 있음/확인함(`known`), 모름, 비공개 |
| 어떤 부채인가요? | 종류 텍스트 + 내부 ID |
| 남은 잔액은 얼마인가요? | 금액 상태 + 금액 |
| 매달 얼마를 갚고 있나요? | 금액 상태 + 금액 |
| 금리는 얼마인가요? | 0 이상 숫자 또는 미입력 |
| 몇 개월 남았나요? | 1~1200개월 또는 미입력 |
| 어떤 방식으로 갚나요? | 원리금균등 / 원금균등 / 만기일시 / 모름 |
| 함께 살기 시작한 뒤에도 유지하나요? | 현재 v3 저장값은 유지(`keep`). 정리는 별도의 상환 일정으로 기록 |
| 일부·전액 상환 뒤 월 납입액은 얼마인가요? | 부채별 금액 상태 + 금액 |

### 4.4 자산과 실제 투입 재원

자산 보유액과 이번 계획에 실제로 쓸 돈을 분리해서 답한다.

| 질문 | 선택지·답변 형식 |
|---|---|
| 어떤 자산인가요? | 현금·예적금 / 임대보증금 / 투자자산 / 청약 / 부동산 / 기타 |
| 현재 잔액 또는 평가액은 얼마인가요? | 금액 상태 + 금액 |
| 언제 사용할 수 있나요? | 날짜 또는 미입력 |
| 이번 계획에 사용할 재원은 무엇인가요? | 위 자산 또는 지원금 / 새 차입 |
| 실제 사용할 예정 금액은 얼마인가요? | 금액 상태 + 금액 |
| 재원은 언제 들어오나요? | 날짜 또는 미입력 |
| 이 재원은 얼마나 확실한가요? | 현재 사용 가능 / 확인된 예정 / 예상 / 모름 |
| 어디에 얼마를 배정하나요? | 주거 / 공동 목표 / 남겨둘 비상금 각각 원 단위 금액 |
| 이 재원으로 먼저 갚을 부채가 있나요? | 부채 ID, 상환 금액, 상환일, 재원별 분담액 |

추가 재원 상태도 `known / unknown / withheld`로 구분한다. 지원금과 새 대출은 보유 자산으로 중복 등록하지 않는다.

## 5. 함께 계산할 공동 계획

| 질문 | 선택지·답변 형식 |
|---|---|
| 언제부터의 생활을 계산할까요? | `YYYY-MM` 시작월 |
| 집은 어떻게 할 계획인가요? | 현재 집 유지 / 월세 / 전세 / 매매 |
| 함께 산 뒤 월 주거비는 얼마인가요? | 금액 상태 + 금액 |
| 보증금 또는 매매대금은 얼마인가요? | 금액 상태 + 금액 |
| 이사·중개·가전 등 한 번만 드는 비용은 얼마인가요? | 금액 상태 + 금액 |
| 돈이 필요한 일정은 어떻게 되나요? | 납부 ID, 날짜, 회차별 금액 |
| 새 주거대출이 있나요? | 부채와 같은 상세 정보 또는 없음 |
| 새 대출금은 언제 사용할 수 있나요? | 날짜 또는 미입력 |
| 새 대출은 얼마나 확실한가요? | 확인됨 / 예상 / 모름 |
| 매달 공동으로 낼 항목은 어디까지인가요? | 주거 / 식비 / 교통 / 구독 / 경조사·선물 / 기타, 항목별 금액 |
| 공동비 범위를 알고 있나요? | known / unknown / withheld |
| 함께 모을 목표가 있나요? | 목표명, 목표액, 목표월 또는 없음 |

공동 계획은 같은 버전을 두 사람이 확인해야 잠긴다. 계획이 수정되면 이전 확인은 해제된다.

## 6. 실제 분담·기준 질문 C1~C6

모두 선택 질문이며, C1·C2는 공동비 예산이 있어야 의미 있게 비교할 수 있다.

| ID | 실제 질문 | 답변 형식 |
|---|---|---|
| C1 | 앞에서 정한 공동비에 본인은 매달 얼마를 내려고 하나요? | 금액 / 모름 / 비공개 |
| C2 | 같은 공동비에 상대가 매달 얼마를 부담하길 기대하나요? | 금액 / 모름 / 비공개 |
| C3 | 주거 초기자금에는 본인 몫으로 얼마를 투입하려고 하나요? | 재원별 주거 배정액 |
| C4 | 매달 꼭 남겨두고 싶은 개인 지출과 저축·비상금이 있나요? | 개인 지출 최소액, 개인 저축 최소액 각각 금액 / 모름 / 비공개 |
| C5 | 이 계획에서 바꾸기 어려운 조건이 있나요? | 아래 구조화 조건 0개 이상 |
| C6 | 이 분담 방식이나 조건을 두 분이 이미 이야기했나요? | 이야기하지 않음 / 이야기 중 / 합의했다고 생각함 / 모름 |

### C5 조건 답변

| 항목 | 선택지·답변 |
|---|---|
| 조건 종류 | 주거비 / 부채 상환 / 차입 / 개인 지출 / 기타 |
| 적용 범위 | 두 사람 공동 / 본인 |
| 강도 | 반드시 지켜야 함 / 가능하면 지키고 싶음 |
| 금액 기준 | 금액 상태 + 금액 |
| 대출 허용 | 허용 / 허용하지 않음 / 미입력 |
| 설명 | 선택 메모, 최대 300자 |

## 8. 공동 대화 전 추가 확인 질문

두 사람이 제출한 뒤, AI 해설 전에 각자 다음 질문에 답한다.

### Q1. 분담액의 의미

**질문:** 앞서 함께 쓸 돈으로 적은 내 금액은 어떤 생각으로 정했나요?

**도움말:** 대화를 시작할 제안인지, 이번에는 더 늘리기 어려운 최대 금액인지 구분한다. 실제 납부 능력이나 두 사람의 합의를 증명하는 값은 아니다.

| 화면 답변 | 서버 값 |
|---|---|
| 이 금액부터 이야기해 보고 싶어요 | `initialProposal` |
| 이번 대화에서 제안할 수 있는 최대 금액이에요 | `selfReportedLimit` |
| 아직 모르겠어요 | `unknown` |

### Q2. 조정 가능한 최대 금액

**질문:** 금액을 조정할 생각이 있다면, 이번 대화에서 어디까지 제안할 수 있나요?

- Q1에서 `initialProposal`을 고른 경우에만 금액을 입력할 수 있다.
- 처음 제안한 금액 이상의 **월 최대 금액**이며, 추가로 더 낼 금액이 아니다.
- 선택 질문이므로 모르면 비워 둘 수 있다.
- 이 답만으로 분담안이나 합의가 바뀌지 않는다.

## 9. 공동 리포트가 만드는 대화 질문

아래 질문은 조건을 만족할 때만 나타난다. 최대 3개가 우선 카드로 선택되지만 전체 이슈는 리포트에 남는다.

| 상황 코드 | 질문 |
|---|---|
| `FUNDING_GAP` | 추가 재원을 확인할까요, 필요한 금액이나 지급일을 조정할까요? |

| `CASHFLOW_UNCERTAIN` | 각자 확인할 수 있는 수치와 상환 후 월 납입액을 보완할까요? |
| `MONTHLY_DEFICIT` | 어떤 지출이나 주거 계획을 조정할까요? |
| `GOAL_UNCERTAIN` | 목표 금액과 기한을 유지할지, 먼저 확인할 수치를 정할까요? |

| `CONTRIBUTION_GAP` | 각자의 분담액과 공동비 예산 중 무엇을 조정할까요? |

| `EXCESS_CONTRIBUTIONS` | 남는 분담금을 어디에 사용할까요? |
| `EXPECTATION_DIFFERENCE` | 같은 공동비 범위를 생각했나요? 금액과 포함 항목을 확인해 주세요. |

| `BORROWING_CONDITION` | 차입 계획과 조건 중 어느 쪽을 다시 검토할까요? |

## 10. AI 해설 카드의 질문

AI 해설은 최대 3개 카드이며 각 카드는 다음 구조다.

1. 서버가 확정한 이슈와 근거 수치
2. 그 사실의 의미를 설명하는 해설
3. 두 사람이 다음에 이야기할 한 문장 질문

AI가 실패하거나 비활성화되면 같은 구조의 고정 템플릿 질문을 사용한다. 주요 기본 질문은 다음과 같다.

| 상황 | 기본 질문 예시 |
|---|---|
| 주거자금 부족 | 납부 전에 확보할 재원을 확인할까요, 주거 금액이나 납부 일정을 다시 정할까요? |
| 주거 정보 미정 | 어떤 금액이나 날짜를 누가 확인하고, 언제 다시 이야기할까요? |
| 예상 재원 포함 | 예상한 돈이 늦게 들어오거나 줄어들면 어떤 계획부터 조정할까요? |
| 월 적자 | 지출 항목과 주거 계획 중 무엇을 조정하고, 바꾼 수치로 다시 계산할까요? |
| 목표 적립 부족 | 목표 금액·기한·월 지출 중 바꿀 수 있는 항목과 유지할 항목을 정할까요? |
| 조건 논의 필요 | 지켜야 하는 조건과 조정할 수 있는 조건을 구분하고, 예외와 재검토일을 정할까요? |
| 분담 공백 | 현재 합의와 각자의 상한을 확인한 뒤, 공동 예산과 제안 금액 중 무엇을 조정할까요? |
| 분담액 미정 | 각자가 제시할 수 있는 금액부터 확인할까요, 공동 예산부터 조정할까요? |
| 분담액 초과 | 현재 합의를 확인한 뒤, 예산을 넘는 제안분의 용도나 분담액을 정할까요? |
| 상대 기대와 제안 차이 | 상대의 제안이 협상 시작점인지 본인이 정한 상한인지 확인하고, 기대 금액을 다시 이야기할까요? |

추가 확인 답변에 따라 질문은 더 구체적으로 바뀔 수 있다. 예를 들어 한 사람이 `selfReportedLimit`을 골랐다면 그 상한을 존중한 채 공동예산 축소 또는 다른 사람의 조정 범위를 확인하도록 묻는다.

현재 AI 카드의 `question`은 **함께 이야기하기 위한 프롬프트**다. AI와 자유 대화를 이어가는 채팅 입력이나, AI 질문에 대한 임의 답변을 서버에 저장하는 기능은 아니다. 답변을 기준표로 남기려면 아래의 구조화된 제안·확인 흐름을 사용한다.

## 11. 질문 뒤에 남기는 우리 돈의 기준표

대화를 마친 뒤에는 자유 문장만 남기지 않고 다음 항목으로 제안한다.

| 항목 | 답변 형식 |
|---|---|
| 주제 | 월 분담 / 주거자금 / 저축 / 소비 / 투자 / 부채 / 공동관리 / 기타 |
| 정한 범위 | 최대 300자 |
| 담당 | A / B / 둘 다 |
| 시작월 | `YYYY-MM` |
| 납부일 | 매월 1~31일 또는 없음 |
| 각자 월 분담액 | 월 분담 주제일 때 A·B 금액 모두 필수 |
| 공동비 포함 항목 | 주거 / 식비 / 교통 / 구독 / 경조사·선물 / 기타 |
| 예외 | 최대 300자 |
| 다시 볼 날짜 | 날짜 또는 없음 |
| 상태 | 제안됨 / 둘 다 확인 / 보류 |

한쪽이 제안한 것만으로 합의가 되지 않는다. 두 사람이 같은 버전을 확인해야 `둘 다 확인`이 되며, 금액·범위·날짜·예외를 수정하면 확인이 다시 해제된다.

## 12. 짧은 예시

공동비가 월 200만 원이고 A와 B가 각각 80만 원을 제안했다고 가정한다.

1. 서버는 `40만 원의 분담 공백`을 계산한다.
2. 두 사람에게 각 80만 원이 시작 제안인지 최대 금액인지 묻는다.
3. AI 또는 기본 템플릿은 “각자의 상한과 현재 합의를 확인한 뒤 공동예산과 제안 금액 중 무엇을 조정할까요?”라고 묻는다.
4. 두 사람은 각자 100만 원, 매월 25일, 주거·식비 포함 같은 구조화된 기준을 제안할 수 있다.
5. 두 사람이 같은 버전을 확인하면 기준표에 `둘 다 확인`으로 표시된다.

이 과정에서 가치관 점수는 누가 더 옳은지 판정하지 않고, AI도 금액이나 합의를 대신 결정하지 않는다.
